\chapter{The services}
\label{ch:i-services}

Each host runs its part of the stack as a systemd service under a watchdog: it starts at boot,
restarts when something it depends on goes away, and is never given up on.

\section{Install}

The same on each host:

\begin{lstlisting}[language=bash]
cd ~/x30_ws/src/x30_ros/tools
sudo bash x30_host.sh install
\end{lstlisting}

The role comes from the host's address: \code{navigation} on .106, \code{perception} on .105. A
role named for the other host is refused, and a service an older x30\_host.sh put on the wrong
host is removed with its settings. This writes \file{/etc/systemd/system/x30-<role>.service} and its settings file
\file{/etc/x30/<role>.env} (mode 600: root and \code{ysc} only), and enables the service. Run it
with the robot up: the navigation host's service is ordered after Deep Robotics' services and
the one running the ROS master, as it finds them. At the end it prints the next commands: the
settings to edit, then the service's start and its log.

\begin{warnbox}[An existing settings file is kept]
\cmd{install} never overwrites \file{/etc/x30/<role>.env}. On a robot installed before
version~0.19, add the line \code{X30_NETRA_TOKEN=} to \file{/etc/x30/navigation.env} yourself.
\end{warnbox}

\section{Settings}

\file{/etc/x30/navigation.env} (shell words: a quoted value stays one argument; NETRA's
arguments join \code{X30_LAUNCH_ARGS} in Chapter~\ref{ch:i-netra}):

\begin{lstlisting}[language=bash]
X30_LAUNCH_ARGS="site:=gardu controller:=neupan"
# only for controller:=neupan
X30_PYTHON=/home/ysc/x30_ws/neupan/bin/python
X30_TELEOP_TOKEN=<the handheld's token>
X30_NETRA_TOKEN=<CC_TOKEN from NETRA>
# each node's JSON lines log
# X30_LOG_DIR=/home/ysc/x30/logs
# ROS's own logs, pruned at every start (MB)
# X30_ROS_LOG_MB=2048
\end{lstlisting}

\file{/etc/x30/perception.env}:

\begin{lstlisting}[language=bash]
# e.g. hikmicro_host:=192.168.1.64 hertzino_host:=192.168.2.204
X30_LAUNCH_ARGS=""
HIKMICRO_PASSWORD=<thermal camera admin password>
HERTZINO_PASSWORD=<acoustic camera password>
\end{lstlisting}

\begin{warnbox}[A comment goes on a line of its own]
systemd reads no comment after a value: whatever follows a value on its line becomes part of
it, the comment's words in a token, a password or the launch arguments.
\end{warnbox}

\section{Start, stop, watch}

The navigation host first: the perception host uses its master. On .106:

\begin{lstlisting}[language=bash]
sudo systemctl restart x30-navigation
\end{lstlisting}

Then on .105:

\begin{lstlisting}[language=bash]
sudo systemctl restart x30-perception
\end{lstlisting}

The watchdog's status line, the log and the check, here on .106 (\code{x30-perception} on .105):

\begin{lstlisting}[language=bash]
systemctl status x30-navigation
journalctl -u x30-navigation -f
bash ~/x30_ws/src/x30_ros/tools/x30_host.sh check
\end{lstlisting}

\cmd{x30_host.sh check} tells this host's role and address, whether the other host answers,
the ROS master and every registered node from here, the two clocks, and on the navigation host
that Deep Robotics' autonomy is off, on the perception host the cameras' ports.

\section{What the watchdog does}

The service's main process starts the host's launch file, tells systemd it is ready once the
master and the critical nodes answer (on the navigation host: the driver, the control mux, the
LiDAR scans and the path follower), then checks them every 5~s. The service restarts when:

\begin{itemize}
  \item the master restarted (its nodes are lost with it; the perception host follows this way);
  \item the master or a critical node stays away longer than 45~s;
  \item the start takes longer than 4~min, or roslaunch exits;
  \item the watchdog itself hangs (systemd's \code{WatchdogSec=60}).
\end{itemize}

Meanwhile the robot stands: the control mux stops a command that is not renewed, and the motion
host stops taking commands without the driver's heartbeat. On the navigation host the watchdog
also turns off, every 30~s, whatever of Deep Robotics' autonomy one of its services started
again late, and names it in the journal.

\section{Run by hand}

For a test without the services (stop them first), on each host this shell's ROS network:

\begin{lstlisting}[language=bash]
eval "$(bash ~/x30_ws/src/x30_ros/tools/x30_host.sh env)"
\end{lstlisting}

Then on .106:

\begin{lstlisting}[language=bash]
roslaunch x30_bringup navigation_host.launch site:=gardu
\end{lstlisting}

And on .105:

\begin{lstlisting}[language=bash]
roslaunch --wait x30_bringup perception_host.launch
\end{lstlisting}
