\chapter{Updates and backups}
\label{ch:i-updates}

\section{A new version of the stack}

On the Mac, online:

\begin{lstlisting}[language=bash]
cd ~/x30/x30_ros
git pull
bash tools/pack_sources.sh ~/x30/x30_sources.tar.gz
\end{lstlisting}

At the robot, to both hosts:

\begin{lstlisting}[language=bash]
cd ~/x30
scp x30_sources.tar.gz ysc@192.168.1.106:~/
scp x30_sources.tar.gz ysc@192.168.1.105:~/
\end{lstlisting}

On each host a clean workspace and its build (Section~\ref{sec:i-build}):

\begin{lstlisting}[language=bash]
cd ~/x30_ws
rm -rf src.prev build devel
mv src src.prev
tar -xzf ~/x30_sources.tar.gz
bash src/x30_ros/tools/check_deps.sh
bash src/x30_ros/tools/x30_host.sh build
\end{lstlisting}

The build ends with the host's restart: \cmd{sudo systemctl restart x30-navigation} on .106,
\cmd{sudo systemctl restart x30-perception} on .105; the services stay installed. A new version
may need a new package (\file{check_deps.sh} says so); the \code{CHANGELOG.md} of x30\_ros says
what changed and whether a settings file needs a new line.

\section{A new app}

\begin{lstlisting}[language=bash]
cd ~/x30
gh release download -R DarmawanRobotics/X30Controller \
  -p 'x30-controller-*.apk' --clobber
adb install -r x30-controller-*.apk
\end{lstlisting}

\section{A new NETRA}

Online:

\begin{lstlisting}[language=bash]
cd ~/x30/Netra
git pull
git submodule update --init --recursive
scripts/local.sh up
\end{lstlisting}

\cmd{up} rebuilds what changed.
